# مصفوفة الاختبار التكاملي لنظام SchoolSystem

## نطاق المرحلة الحالية

تم فحص مسار **التسجيل → الشعب → توزيع الفصول → الدرجات → التقارير والتصدير** تحليلياً على نسخة المستودع الحالية `1a4c947`. بيئة الوكيل Linux لا تشغّل WinForms أو SQL Server المحلي الخاص بجهاز Windows، لذلك يميّز هذا المستند بين الفحص الساكن الذي تم تنفيذه والاختبار التشغيلي الذي يجب تنفيذه على جهاز التطوير.

| المسار | نتيجة الفحص الساكن | ملاحظة التحقق التشغيلي |
|---|---|---|
| تحميل الصفوف | سليم من ناحية استدعاء الخدمة والصلاحيات متعددة الأدوار | اختيار صف فعلي من قاعدة `SchoolDB` |
| تحميل الشعب | `StudentClassService.GetSections` يستخدم `DemandAny` لصلاحيات التسجيل والتوزيع والحضور والدرجات والجدول والتقارير | تسجيل الدخول بمستخدم محدود ثم اختيار صف وعام دراسي |
| منع الشعب الفارغة | الاستعلامات تستبعد `NULL` والنصوص الفارغة بعد `LTRIM/RTRIM` | التأكد من عدم ظهور عنصر فارغ في القوائم |
| العام الدراسي | الخدمات توحّد الشرطة إلى `/`، والتحقق يفرض صيغة متسلسلة مثل `2026/2027` | تجربة تاريخ قبل/بعد شهر أغسطس |
| منع التوزيع المكرر | الخدمة تتحقق من وجود توزيع سابق في العام نفسه قبل الإدراج | تجربة حفظ الطالب نفسه مرتين |
| مخطط الدرجات | النسخة الحالية تحتوي مواءمة مع جدول `Grades` في آخر التزام | إدخال درجة ثم إعادة تحميلها من الشاشة |
| التقرير | خدمة التقارير تتحقق من `Reports.View` وتعيد الشعب بحسب الصف والعام | تشغيل تقرير صف وشعبة محددين |
| Excel | المرجع `System.ValueTuple` موجود مع `Private=True` وbinding redirect في `App.config` | تنفيذ Restore ثم Rebuild وحذف `bin/obj` قبل تجربة التصدير |
| PDF | الإخراج يختار الخط العربي من مجلد Fonts ويضبط اتجاه الخلية حسب النص | تجربة بيانات عربية وإنجليزية مختلطة |

## اختبار التشغيل على جهاز Windows

ينفذ المطور الأوامر التالية من مجلد المشروع بعد إغلاق Visual Studio أو بعد حفظ التغييرات المحلية:

```powershell
git switch main
git pull --ff-only origin main
nuget restore SchoolSystem.sln
Remove-Item -Recurse -Force .\bin, .\obj -ErrorAction SilentlyContinue
```

بعد ذلك يُفتح الحل في Visual Studio 2022، ويُنفّذ **Clean Solution** ثم **Rebuild Solution**. يجب التأكد من وجود `System.ValueTuple.dll` وملفات ClosedXML التابعة في مجلد `bin\Debug` أو `bin\Release`. إذا لم تظهر، تُفحص مراجع NuGet وتُعاد استعادة الحزم بدلاً من نسخ DLL يدوياً.

## سيناريو القبول المتكامل

ينشئ المسؤول أو يستخدم طالباً نشطاً، وصفاً فعالاً، وشعبة فعالة في العام الدراسي الحالي. من شاشة التسجيل والقبول يتم اختيار الصف، ثم يجب أن تظهر الشعب غير الفارغة في القائمة. بعد الحفظ، تُفتح شاشة توزيع الفصول ويُختار الصف والعام والشعبة، ثم يُوزع الطالب مرة واحدة. بعد ذلك تُفتح شاشة الدرجات، ويُختار الصف والشعبة والمادة، وتُحفظ درجة صحيحة، ثم يُعاد تحميلها. أخيراً يُشغّل تقرير الطلاب أو الدرجات مع نفس العام والشعبة، ويُختبر التصدير إلى Excel وPDF والطباعة مع بيانات عربية وإنجليزية.

## معيار النجاح

يُعد المسار ناجحاً إذا لم تظهر رسالة `UnauthorizedAccessException` لمستخدم يمتلك إحدى صلاحيات القراءة المعتمدة، ولم تظهر شعبة فارغة، ولم يحدث تكرار لتسجيل أو توزيع الطالب في العام نفسه، ولم يفشل الإدراج بسبب اختلاف أسماء أعمدة `Grades`، ونجح إنشاء ملفي Excel وPDF في مجلد قابل للكتابة مع اتجاه عربي صحيح.

## قيد مهم

لا يمكن اعتماد نجاح التشغيل الفعلي من بيئة Linux الحالية؛ فالاعتماد النهائي يتطلب تشغيل السيناريو السابق على جهاز Windows المتصل بقاعدة `SchoolDB` الفعلية. أي خطأ SQL أو صورة شاشة تظهر هناك يجب إرفاقه مع نص الاستثناء واسم النموذج حتى يُعالج في الالتزام التالي.
