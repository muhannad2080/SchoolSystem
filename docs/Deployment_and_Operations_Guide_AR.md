# دليل تشغيل وتسليم نظام SchoolSystem

## 1. نطاق الدليل

يوضح هذا الدليل طريقة جلب النسخة الصحيحة من مستودع GitHub، تجهيز SQL Server، ضبط اتصال التطبيق، بناء مشروع WinForms داخل Visual Studio، وتنفيذ اختبار تشغيل أولي آمن. يُنصح بتنفيذ الخطوات على قاعدة اختبار قبل ربط التطبيق ببيانات حقيقية.

## 2. المتطلبات

| المكوّن | المتطلب |
|---|---|
| نظام التشغيل | Windows يدعم Visual Studio وSQL Server |
| بيئة التطوير | Visual Studio 2022 مع أدوات .NET Framework desktop development |
| إطار العمل | .NET Framework 4.7.2 |
| قاعدة البيانات | SQL Server أو SQL Server Express |
| لغة التطبيق | C# وWindows Forms |
| المستودع | `muhannad2080/SchoolSystem` والفرع `main` |

## 3. جلب النسخة من GitHub

افتح PowerShell في مجلد المشروع ونفذ الأوامر التالية. استخدام `--ff-only` يمنع إنشاء دمج غير مقصود أو فقدان تغييرات محلية.

```powershell
git switch main
git pull --ff-only origin main
git status -sb
git rev-parse HEAD
git rev-parse origin/main
```

يجب أن تكون نتيجة الحالة شبيهة بـ `main...origin/main`، ويجب أن يتطابق ناتجا `rev-parse`.

إذا ظهرت تغييرات محلية، لا تنفذ `reset --hard` مباشرة. احفظها أولًا باستخدام نسخة احتياطية أو `git stash`، ثم راجعها قبل متابعة السحب.

## 4. إنشاء قاعدة البيانات

افتح SQL Server Management Studio واتصل بالخادم المطلوب. أنشئ قاعدة باسم `SchoolDB` أو استخدم اسم القاعدة الموجود في اتصال التطبيق. شغّل `Databass/SchoolDB.SQL` أولًا، ثم نفذ الترحيلات اللازمة بالترتيب الوظيفي.

| المرحلة | الملفات النموذجية |
|---|---|
| المخطط الأساسي | `Databass/SchoolDB.SQL` |
| الجداول التشغيلية | `Databass/Migration_OperationalTables.sql` و`Migration_MissingApplicationTables.sql` |
| التسجيل والأقسام | `Migration_CreateSchoolSections.sql` و`Migration_NormalizeExistingSections.sql` |
| الترقيم ومنع التكرار | `Migration_AutomatedNumbering.sql` و`Migration_AddDuplicatePreventionConstraints.sql` |
| RBAC | `Migration_RBAC_NormalizedCatalog.sql` و`Migration_RBAC_SyncCatalog.sql` و`Migration_RBAC_Hardening.sql` |
| التدقيق | `Migration_AuditLog.sql` و`Migration_AuditLog_Enrichment.sql` |
| الماليات والدرجات | `Migration_HardenFeePlans.sql` و`Migration_GradesComponents.sql` |
| الإعدادات | `Migration_SettingsBackup.sql` |

لا تشغل ملفات `Seed_*` على قاعدة إنتاج؛ فهي مخصصة لبيئة العرض والاختبار. ولتفريغ البيانات التشغيلية مع إبقاء المستخدمين والصلاحيات، راجع `Databass/Clear_AllOperationalData_KeepSecurity.sql` وتحقق من اسم القاعدة قبل التنفيذ.

## 5. ضبط الاتصال

يقرأ التطبيق إعدادات الاتصال من `App.config`. تأكد من أن اسم الخادم، اسم قاعدة البيانات، وطريقة المصادقة مناسبة للجهاز. لا تضع كلمة مرور قاعدة البيانات في مستودع عام أو داخل رسالة خطأ.

بعد تعديل الاتصال، اختبر الوصول من SQL Server Management Studio أولًا، ثم شغّل التطبيق. رسالة فشل الاتصال يجب أن تكون مفهومة للمستخدم دون كشف نص SQL أو بيانات اعتماد.

## 6. البناء في Visual Studio

افتح ملف الحل `.sln` داخل Visual Studio، وتأكد من اختيار `Debug` أو `Release` و`Any CPU` حسب بيئة التشغيل. نفذ بالترتيب:

```text
Build > Clean Solution
Build > Rebuild Solution
```

يجب ألا توجد أخطاء `CS` في قائمة Error List. تحذيرات التحليل البرمجي لا تمنع التشغيل عادة، لكن يُفضّل مراجعتها قبل التسليم النهائي. بعد نجاح البناء شغّل المشروع بواسطة `F5`.

## 7. التشغيل الأول

عند فتح شاشة الدخول، استخدم حساب مدير النظام المجهز في قاعدة الاختبار. بعد الدخول تحقق من ظهور الشاشة الرئيسية، واسم المستخدم، والوحدات المسموحة. لا تفترض أن ظهور لوحة التحكم والتقارير يعني منح كل الصلاحيات؛ يجب اختبار صلاحيات الوحدات والإجراءات من واجهة المستخدم نفسها.

إذا كانت قاعدة الاختبار جديدة ولا يوجد حساب دخول، استخدم سكربت التهيئة المعتمد في بيئة المشروع أو أنشئ المستخدم من مسار الإدارة المخصص. لا تُدخل كلمات المرور مباشرة في أعمدة التجزئة يدويًا.

## 8. اختبار الصلاحيات

أنشئ ثلاثة سيناريوهات اختبار: مدير نظام، مستخدم بصلاحية الطلاب عرض فقط، ومستخدم بلا صلاحيات تشغيلية. امنح أو ألغِ الصلاحية من واجهة المستخدم، احفظ، سجّل الخروج، ثم سجّل الدخول مرة أخرى. يجب أن تُحفظ النتيجة في قاعدة البيانات وألا تعود الصلاحيات الافتراضية القديمة للمستخدم العادي.

اختبر كل إجراء على حدة: View وAdd وEdit وDelete وPrint وExport. إخفاء الزر تحسين للواجهة، لكنه ليس الحماية الوحيدة؛ الحارس الفعلي موجود داخل الخدمات عبر `CurrentUser.DemandAction`.

## 9. اختبار قفل الحساب

على مستخدم غير مدير، أدخل كلمة مرور غير صحيحة ثلاث مرات. يجب أن يسجل النظام المحاولات، يعطل الحساب، يسجل حدث التدقيق، ويعرض رسالة واضحة. اختبر بعدها محاولة الدخول بالحساب المقفل. لا تنفذ هذا الاختبار على حساب المدير أو قاعدة الإنتاج.

لإعادة حساب اختبار مقفل، استخدم `Databass/Unlock-LockedAccounts.sql` بعد مراجعة اسم المستخدم والقاعدة، ثم تحقق من النتيجة قبل إعادة الاختبار.

## 10. اختبار البحث والتقارير

في كل شاشة تحتوي على بحث، اكتب حرفًا أو رقمًا واحدًا، ثم أضف بقية الكلمة، ثم أدخل كلمتين تفصل بينهما مسافة. يجب أن تتغير النتائج مع كل إدخال، وأن تُبحث الكلمات كلها عبر الأعمدة المحددة. عند مسح الحقل يجب أن تعود النتائج العامة.

اختبر مركز التقارير بالفلاتر، زر مسح الفلاتر، الطباعة والتصدير. افتح CSV ببرنامج يدعم UTF-8 وتأكد من ظهور العربية. اختبر PDF وExcel للتأكد من عدم قص النصوص أو اختفاء الأعمدة.

## 12. النسخ الاحتياطي والاستعادة

نفذ النسخ الاحتياطي إلى مسار مطلق خارج مجلد التطبيق، مثل `D:\SchoolBackups\SchoolDB`. تحقق من وجود الملف وحجمه قبل اعتباره ناجحًا. قبل الاستعادة أغلق التطبيق وكل الاتصالات الأخرى، ثم استخدم شاشة الإعدادات أو المسار المعتمد في `DatabaseBackupService`.

لا تستعد نسخة فوق قاعدة إنتاج دون نسخة احتياطية إضافية. بعد الاستعادة تحقق من عودة وضع القاعدة إلى `MULTI_USER`، ثم افتح التطبيق واختبر الدخول والصلاحيات والبيانات الأساسية.

## 13. معالجة الأخطاء الشائعة

| الخطأ | الإجراء |
|---|---|
| `Your branch is behind` | نفذ `git pull --ff-only origin main` قبل التعديل أو الرفع |
| تعارض Designer | أغلق المصمم، احفظ نسخة من الملف، راجع التغييرات، ثم أعد البناء |
| فشل الاتصال | راجع اسم الخادم والقاعدة وطريقة المصادقة في `App.config` |
| جدول غير موجود | نفذ مخطط `SchoolDB.SQL` ثم الترحيلات المطلوبة بالترتيب |
| الصلاحيات تعود افتراضية | احفظ التعديل، سجل الخروج، تحقق من جدول الصلاحيات، ثم أعد الدخول |
| زر غير ظاهر | نفذ `Clean` و`Rebuild` وافحص `Visible` و`Dock` و`Anchor` في Designer |
| فشل التصدير العربي | تحقق من UTF-8 BOM للـCSV وخطوط RTL لمخرجات PDF |

## 14. التسليم النهائي

قبل تسليم النسخة للدكتور، يجب إرفاق رقم الالتزام، نسخة قاعدة اختبار، لقطات لحالات الصلاحيات، تقرير اختبار Windows، ونسخة من `docs/SchoolSystem_Defense_Guide_AR.md` و`docs/Windows_Acceptance_Test_Matrix.md`. يجب إخفاء كلمات المرور ومعلومات الاتصال الحساسة من اللقطات والملفات المرسلة.

أوامر التحقق النهائي من المزامنة هي:

```powershell
git status -sb
git fetch origin main
git rev-parse HEAD
git rev-parse origin/main
```

إذا تطابق المعرفان ولم توجد تغييرات محلية، تكون نسخة الجهاز متزامنة مع GitHub.
