# سجل تنفيذ سيناريو النظام الكامل

## الحالة

هذا الملف هو سجل متابعة تنفيذ السيناريو التشغيلي الكامل. تم إنشاء الجرد الأولي للواجهات والخدمات والصلاحيات ومسارات الحفظ قبل تعديل أي وظيفة.

## الوحدات المشمولة

| الوحدة | الواجهة/الواجهات | الحالة الأولية | اختبار القبول المطلوب |
|---|---|---|---|
| الدخول | LoginForm، MainForm | موجودة | الدخول والخروج وبناء القائمة حسب الصلاحيات |
| المستخدمون والصلاحيات | UsersForm، ChangePasswordForm، AuthorizationService | موجودة | منح وإلغاء كل شاشة وإعادة تسجيل الدخول |
| الطلاب | StudentsForm، StudentProfileForm | موجودة | هوية واحدة ومنع الرقم الوطني المكرر |
| التسجيل والقبول | EnrollmentForm، EnrollmentService | موجودة | حالات جديد/مقبول/مرفوض وربط العام |
| التوزيع | ClassAssignmentForm، StudentClassService | موجودة | القبول أولاً، توزيع واحد سنوياً، منع السعة |
| الصفوف والقاعات | ClassesForm، RoomsForm/ClassesForm | موجودة جزئياً | توليد الرقم والكود والقوائم وعدم التكرار |
| المواد | SubjectsForm | موجودة | رمز فريد وربط الصف عند الحاجة |

| الإعدادات والنسخ | SettingsForm | موجودة | إعداد المدرسة ونسخ احتياطي واستعادة اختبارية |

## قاعدة التحقق المتسلسلة

`طالب → تسجيل → قبول → توزيع → خطة رسوم → رسوم → سداد → سند`

`صف + شعبة + مادة + معلم + قاعة + وقت → جدول`

`موظف + عقد ساري → راتب`

## نتائج الفحص الأولي

تم التأكد من وجود ملفات الواجهات والخدمات والمستودعات الأساسية في المشروع، ومن وجود مسارات حماية للصلاحيات ورسائل أخطاء عربية في عدد كبير من العمليات. كما تم تحديد أن التحقق الفعلي من قاعدة البيانات والبناء النهائي يحتاج إلى بيئة Windows/SQL Server متصلة بقاعدة الاختبار.

## منهج التنفيذ التالي

1. مراجعة كل وحدة على مستوى Model ثم Repository ثم Service ثم Form.
2. إضافة أو تشديد قيود التكرار والعلاقات دون حذف بيانات صحيحة.
3. اختبار كل عملية نجاح وفشل على مستوى الكود، ثم تنفيذ اختبار قبول على Windows.
4. تحديث هذا الملف بعد كل مرحلة مع الملفات والاختبارات والنتائج.

## ملاحظة مهمة

نجاح الفحص النصي أو البناء لا يثبت وحده اكتمال النظام. يجب إعادة فتح الشاشة وفحص النتيجة من قاعدة البيانات وتنفيذ الاختبار السلبي المقابل لكل قاعدة عمل.
