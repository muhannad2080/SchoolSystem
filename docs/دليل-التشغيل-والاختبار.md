# دليل تشغيل واختبار نظام SchoolSystem

## 1. متطلبات التشغيل

يحتاج النظام إلى جهاز Windows، وVisual Studio 2019 أو أحدث، و.NET Framework 4.7.2، وSQL Server يمكن الوصول إليه من الجهاز، وحزم NuGet الموجودة في المشروع. لا يكفي نسخ ملفات C# فقط؛ يجب أن تكون قاعدة البيانات والحزم وإعدادات الاتصال صحيحة.

| العنصر | المطلوب |
|---|---|
| نظام التشغيل | Windows لأن التطبيق WinForms. |
| بيئة التطوير | Visual Studio مع workload الخاص بـ .NET Desktop Development. |
| Framework | .NET Framework 4.7.2. |
| قاعدة البيانات | SQL Server وقاعدة باسم `SchoolDB`. |
| الاتصال | Windows Authentication أو سلسلة اتصال مكافئة حسب البيئة. |
| الحزم | استعادة `packages.config` قبل البناء. |

## 2. جلب آخر نسخة

```powershell
git switch main
git pull --ff-only origin main
```

إذا كانت هناك تعديلات محلية غير محفوظة، يجب حفظها أو عمل stash قبل `pull` حتى لا تُستبدل ملفات Designer.

## 3. استعادة الحزم والبناء

من Visual Studio استخدم Restore NuGet Packages، أو من مجلد الحل:

```powershell
nuget.exe restore SchoolSystem.sln
```

ثم افتح `SchoolSystem.sln`، اختر `Debug` و`Any CPU`، واضغط:

```text
Build → Rebuild Solution
```

بعد نجاح البناء شغل التطبيق بواسطة `F5`.

## 4. إعداد الاتصال

افتح `App.config` وابحث عن:

```xml
<connectionStrings>
  <add name="SchoolDBConnection"
       connectionString="Server=SERVER_NAME;Database=SchoolDB;Trusted_Connection=True;" />
</connectionStrings>
```

استبدل `SERVER_NAME` باسم SQL Server الموجود في جهازك. بعد ذلك افتح SQL Server Management Studio واتصل بنفس الخادم وتأكد من وجود `SchoolDB`.

## 5. إنشاء قاعدة البيانات

شغل ملف إنشاء القاعدة والمخطط أولًا، ثم ملفات Migration بالترتيب. يجب تنفيذ السكربتات داخل قاعدة `SchoolDB` وليس `master`.

```sql
USE SchoolDB;
GO
```

بعد تنفيذ المخطط، يمكن تشغيل ملفات البيانات التجريبية الموجودة في `Databass/Seed_*.sql`. لا تشغل بيانات تجريبية قبل التأكد من وجود الجداول والأعمدة المطلوبة.

## 6. تشغيل بيانات العرض

بيانات العرض تساعد في اختبار التقارير والشعب والطلاب والمعلمين. شغل سكربتات seed المناسبة، ثم تحقق من:

```sql
SELECT COUNT(*) FROM dbo.Students;
SELECT COUNT(*) FROM dbo.Teachers;
SELECT COUNT(*) FROM dbo.Classes;
SELECT COUNT(*) FROM dbo.Subjects;
SELECT COUNT(*) FROM dbo.StudentClasses;
SELECT COUNT(*) FROM dbo.Enrollments;
SELECT COUNT(*) FROM dbo.Vouchers;
```

يجب أن تكون الشعب مرتبطة بالصفوف، وأن تحتوي سجلات توزيع الطلاب على `Section` و`AcademicYear`.

## 7. تنظيف البيانات دون حذف الأمان

قبل التنظيف خذ نسخة احتياطية. الملف المخصص لذلك هو:

```text
Databass/Clear_AllOperationalData_KeepSecurity.sql
```

وظيفته إزالة البيانات التشغيلية والتجريبية مع إبقاء المستخدمين ومدير النظام وإعدادات الأمان. لا تستخدم أوامر `TRUNCATE` أو `DELETE` عشوائية على جداول `Users` أو سجلات الصلاحيات.

## 8. سيناريو اختبار الدخول

ابدأ بمدير النظام وتحقق من ظهور اللوحات الرئيسية والإعدادات وسجل الأنشطة والخروج. بعد ذلك أنشئ أو استخدم مستخدمًا محدود الصلاحيات، وسجل الدخول به، وتأكد أن الوحدات غير المسموح بها لا يمكن تنفيذها حتى لو حاول المستخدم استدعاء عملية مباشرة.

اختبر كلمة المرور الخاطئة عدة مرات للمستخدم العادي، وتأكد من ظهور رسالة واضحة عند القفل. اختبر مدير النظام بشكل منفصل، لأن سياسة القفل لا تطبق عليه وفق متطلبات النظام.

## 9. سيناريو اختبار الطلاب

افتح شاشة الطلاب وأنشئ طالبًا جديدًا. املأ الاسم والبيانات المطلوبة، ثم اضغط حفظ. تحقق من ظهور الطالب في الجدول، ثم اختبر البحث من أول حرف أو رقم. حدد الصف، افتح الملف الشخصي، وجرب التصدير والطباعة إذا كانت البيئة تحتوي على الحزم المطلوبة.

## 10. سيناريو اختبار التسجيل والقبول

اختر طالبًا، ثم الصف، ثم العام الدراسي. يجب أن تُحمّل قائمة الشعب بعد اختيار الصف. اختر شعبة صحيحة واضغط حفظ. أعد المحاولة بنفس الطالب والعام، وتأكد من ظهور رسالة منع التكرار بدل إنشاء تسجيل ثانٍ.

إذا كانت قائمة الشعب فارغة، تحقق بالترتيب من اتصال قاعدة `SchoolDB`، ووجود الصف، ووجود الشعب، وتطابق العام الدراسي، وصلاحية `ClassAssignment.Manage`.

## 11. سيناريو اختبار السندات

افتح السندات واضغط **سند قبض جديد**. يجب أن يظهر رقم يبدأ عادةً بـ `REC`. ثم اختر طرفًا من القائمة أو اكتب أول حروف اسمه، وأدخل المبلغ والبيان وطريقة الدفع، ثم احفظ.

اضغط **سند صرف جديد**، وتحقق من رقم يبدأ بـ `PAY`. جرّب إنشاء سند مرجع مرتبط دون رقم مرجع، ويجب أن يرفضه النظام. جرّب إنشاء سند بمبلغ صفر أو تاريخ مستقبلي، ويجب أن يرفضه النظام. اختبر تعديل سند تلقائي، ويجب أن يمنعه النظام.

## 12. فحوصات المشروع الساكنة

من Linux أو بيئة CI يمكن تشغيل:

```bash
python3 scripts/static_project_check.py
python3 scripts/static_sql_check.py
python3 tools/check_service_validation_guards.py
```

الأول يفحص ملفات C# وملفات Designer وإدراج الملفات في المشروع. الثاني يفحص أهداف SQL وسلامة بنية السكربتات. الثالث يراجع وجود حواجز التحقق والتسجيل في الخدمات.

## 13. النسخ الاحتياطي والاستعادة

يوجد:

```text
scripts/Backup-SchoolDB.ps1
scripts/Restore-SchoolDB.ps1
Services/DatabaseBackupService.cs
```

قبل الاستعادة أغلق التطبيق، تحقق من اسم قاعدة الهدف، وتأكد أن ملف النسخة الاحتياطية موثوق. بعد الاستعادة نفذ فحصًا لعدد الجداول والطلاب والمستخدمين، ثم جرب الدخول والتقارير.

## 14. أعطال التشغيل المتوقعة

إذا ظهر `Invalid object name` فغالبًا أنت متصل بقاعدة `master` أو لم تطبق Migration. إذا ظهر `Invalid column name` فهناك اختلاف بين نسخة السكربت ونسخة المخطط. إذا ظهرت مشكلة `System.ValueTuple` أو DLL، نفذ Restore للحزم وتحقق من ملفات `bin` و`packages` وbinding redirects. إذا ظهر خطأ صلاحية، راجع الدور والصلاحيات في `PermissionKeys` وبيانات المستخدم.

## 15. ترتيب العرض أمام الدكتور

ابدأ بتشغيل الدخول، ثم اعرض MainForm، ثم افتح شاشة الطلاب، ثم التسجيل، ثم التقارير، ثم السندات. أثناء كل شاشة اشرح قاعدة واحدة داخل الخدمة. لا تشرح الزر باعتباره مجرد زر؛ اشرح أن حدثه يقرأ المدخلات، يبني Model، يستدعي Service، والخدمة تتحقق ثم تستدعي Repository وتعيد النتيجة.
