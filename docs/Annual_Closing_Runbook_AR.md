# دليل الإغلاق السنوي والترحيل

## الهدف

تضمن هذه المرحلة أن العام الدراسي لا يُغلق إلا بعد مراجعة سلامة البيانات الأكاديمية والمالية. الإغلاق لا يحذف السجلات التاريخية ولا يعيد استخدام توزيع أو رسوم العام السابق. أما الترحيل فهو خطة منفصلة قابلة للمراجعة، ولا ينشئ توزيعاً جديداً تلقائياً.

## التثبيت

شغّل الملف `Databass/Migration_AnnualClosingAndStudentMigration.sql` على قاعدة `SchoolDB` بعد تطبيق مخططات الجداول الأساسية. الملف قابل لإعادة التشغيل، وينشئ جدولَي `AnnualClosings` و`AnnualMigrationLog` والإجراءات المخزنة الثلاثة الخاصة بالفحص والإغلاق وتخطيط الترحيل.

| المكوّن | المسؤولية |
|---|---|
| `AnnualClosings` | حفظ حالة العام ووقت الفحص والإغلاق والمستخدم المنفذ |
| `AnnualMigrationLog` | حفظ خطة ترحيل كل طالب من عام إلى عام مرة واحدة فقط |
| `VerifyAnnualClosing` | إظهار الفروقات والسجلات اليتيمة والتكرارات الحرجة |
| `CloseAcademicYear` | منع الإغلاق عند وجود فحص حرج ثم تسجيل الإغلاق داخل معاملة |
| `PlanStudentYearMigration` | إنشاء خطة ترحيل من توزيعات العام المغلق دون إنشاء توزيع جديد |

## السيناريو التشغيلي

ابدأ من واجهة **الإغلاق السنوي والترحيل** الموجودة تحت قائمة الإدارة. اختر العام الدراسي، ثم اضغط **فحص المطابقة**. يجب أن تكون كل الصفوف الحرجة بحالة `سليم`. إذا ظهرت نتيجة تحتاج معالجة، ارجع إلى الواجهة المسؤولة عن السجل، صحح البيانات من خلال الخدمة أو الشاشة المناسبة، ثم أعد الفحص.

بعد نجاح الفحص، أدخل العام التالي بصيغة `2027/2028`، وأدخل ملاحظة إدارية عند الحاجة، ثم اضغط **إغلاق العام** وأكد العملية. سيحفظ النظام حالة العام كمغلق، ويمنع إعادة إغلاقه. لا تُعتبر عملية الإغلاق ترحيلاً للطلاب.

بعد الإغلاق، اضغط **تخطيط الترحيل**. سيظهر سجل مستقل لكل طالب فعّال كان موزعاً في العام السابق. راجع الصف والشعبة المقترحين، ثم نفّذ التوزيع في شاشة **توزيع الطلاب** للعام الجديد بعد مراجعة الإدارة. إذا كان الطالب منقولاً أو معاداً أو مستبعداً، فلا تُنشئ له توزيعاً جديداً من الخطة قبل اتخاذ القرار الإداري الصحيح.

## اختبارات القبول

| الاختبار | النتيجة المتوقعة |
|---|---|
| فحص عام سليم | تظهر نتيجة سليم ويمكن تنفيذ الإغلاق |
| طالب بلا توزيع أو توزيع بلا طالب | يظهر خطأ حرج ويُرفض الإغلاق |
| تسجيل الطالب أكثر من مرة في العام | يظهر تكرار حرج ويُرفض الإغلاق |
| رسم بمبلغ سالب أو دفعة أكبر من الصافي | يظهر خطأ حرج ويُرفض الإغلاق |
| رقم سند مكرر | يظهر خطأ حرج ويُرفض الإغلاق |
| محاولة إغلاق العام نفسه مرة ثانية | تُرفض برسالة عربية ولا تتغير البيانات |
| إدخال العام نفسه كعام تالٍ | تُرفض العملية قبل الوصول إلى قاعدة البيانات |
| تخطيط الترحيل قبل إغلاق العام السابق | تُرفض العملية برسالة واضحة |
| تشغيل تخطيط الترحيل مرتين | لا تتكرر خطة الطالب بسبب القيد الفريد |
| طالب منقول أو مستبعد | لا يُنشأ له توزيع تلقائي؛ يراجع الموظف حالته |

## الصلاحيات

تحتاج الشاشة إلى `AnnualClosing.View` للعرض، وإلى `AnnualClosing.Manage` للفحص التنفيذي وتخطيط الترحيل والإغلاق. مدير النظام يملك الشاشة وفق سياسة الصلاحيات المركزية. يجب منح الصلاحيتين من واجهة إدارة المستخدمين ثم تسجيل الخروج والدخول للتحقق من تحميل الصلاحيات من قاعدة البيانات.

## ملاحظات البناء والتحقق

تم تصميم الواجهة بــ RTL وبعناصر قابلة للتمدد لتقليل احتمالات اختفاء الأزرار أو تداخلها. لا يتوفر مترجم .NET Framework 4.7.2 في بيئة Linux الحالية، لذلك يجب تنفيذ البناء النهائي على Windows باستخدام Visual Studio، ثم تشغيل ترحيل SQL واختبارات القبول على نسخة اختبار من `SchoolDB` قبل الإنتاج.

## المهمة اللاحقة

بعد اعتماد الإغلاق والترحيل، تُستكمل مرحلة **تحديث العام النشط ولوحة التقارير والنسخ الاحتياطي**: اختيار العام الحالي من الإعدادات، عزل التقارير تلقائياً، إنشاء نسخة احتياطية قبل الإغلاق، وإضافة سجل تدقيق لنتيجة الفحص والإغلاق والترحيل.
