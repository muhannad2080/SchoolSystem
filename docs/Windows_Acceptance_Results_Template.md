## 2. طريقة الاستخدام

يُعبّأ هذا النموذج بعد تنفيذ `git pull --ff-only origin main` و`Clean Solution` و`Rebuild Solution` على قاعدة اختبار. لكل حالة، سجّل **ناجح** أو **فشل** أو **غير منفذ**. عند الفشل، اكتب الخطوات الفعلية ورسالة الخطأ كاملة، وأرفق اسم ملف لقطة الشاشة أو مسارها. لا تُخفِ الأخطاء ولا تكتفِ بعبارة عامة مثل «لم يعمل».

| الحالة | معنى القيمة |
|---|---|
| ناجح | النتيجة الفعلية مطابقة للنتيجة المتوقعة |
| فشل | النتيجة الفعلية تختلف أو ظهر استثناء أو فقدت بيانات |
| غير منفذ | تعذر الاختبار بسبب متطلب خارجي، مع توضيح السبب |

## 7. أوامر التحقق من النسخة

```powershell

git status -sb
git rev-parse HEAD
git rev-parse origin/main
```

يُرفق مع النموذج ملف `docs/Windows_Acceptance_Test_Matrix.md`، ونسخة من سجل البناء، ولقطات الشاشة، ورسائل الخطأ الكاملة عند وجود فشل.

## 8. قاعدة تسمية الأدلة

لتسهيل المراجعة، تسمى اللقطات مثلًا `WIN-07-live-search-first-character.png` و`WIN-16-voucher-party-dropdown.png`. تحفظ الأدلة في مجلد خارج ملفات المشروع أو في حزمة التسليم، مع تجنب تصوير كلمات المرور أو بيانات الاعتماد أو معلومات الطلاب الحقيقية غير اللازمة للاختبار.
